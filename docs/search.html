Search Module

Meilisearch integration is implemented as a thin NestJS module: the service owns client bootstrap and index tuning, the controller shapes requests, and the queue worker feeds indexed product documents. The notes below reflect the current code, including the localhost fallback and test-mode disable.

Module wiring Startup initialization Advanced filters Facets and stats Worker indexing

Internal Architecture

  • Module: MeilisearchModule registers the controller and service.
  • Service: MeilisearchService reads env vars, creates the client, and ensures the index exists.
  • Controller: SearchController exposes search, advanced search, suggestions, health, and stats endpoints.
  • Worker: product-sync.processor.ts supplies documents for indexing.

Configuration

Variable Behavior
MEILISEARCH_HOST Defaults to http://127.0.0.1:7700 when missing in local development.
MEILISEARCH_API_KEY Optional unless the Meilisearch instance requires authentication.
MEILISEARCH_INDEX_NAME Defaults to products.
APP_ENV / NODE_ENV If set to test, the service disables Meilisearch access.

The service applies index settings automatically during startup, so behavior stays in sync with code.

Index Settings

  • Searchable: canonicalName, brand, description, category
  • Filterable: category, categoryId, brand, storeNames, bestPrice, currency
  • Sortable: bestPrice, discountPercent, updatedAt
  • Typo tolerance: enabled with thresholds of 5 and 9 characters
  • Pagination: maxTotalHits is capped at 10000

What the API Does

  • Basic search forwards q, limit, offset, filter, and sort.
  • Advanced search builds a filter string from nested filter DTOs and resolves facets, price statistics, and pagination.
  • Suggestions reuse the same index and deduplicate canonicalName values for a lightweight autocomplete response.
  • Health and stats endpoints are operational views of the Meilisearch connection and current indexing state.
