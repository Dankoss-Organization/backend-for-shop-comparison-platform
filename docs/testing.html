Testing Documentation

Practical test guide for this backend: how to run unit tests, database tests, and end-to-end tests with safe local setup and predictable data.

Test Types

Unit / service tests Database tests (Prisma + PostgreSQL) E2E API tests (NestJS + Supertest)
  • Main test command runs Jest test suites from the project root.
  • Database tests use a dedicated PostgreSQL test database and schema reset helpers.
  • E2E tests validate HTTP contracts and integration behavior of API modules.

Available Commands

npm test
npm run test:watch
npm run test:db
npm run test:db:watch
npm run test:e2e

Database Tests: Required Setup

DB tests require a local PostgreSQL URL in .env.test. For safety, the test helper accepts only localhost targets.

  1. Create .env.test in project root.
  2. Set a local test connection string, for example:
DATABASE_TEST_URL=postgresql://postgres:postgres@localhost:5433/shop_comparison_test
  1. Start a test database (Docker compose file is included):
docker compose -f docker-compose.dbtest.yml up -d
  1. Run DB tests:
npm run test:db

What DB Tests Validate

  • Schema integrity and unique constraints (users, offers, diets).
  • Relation behavior and cascade cleanups (users, carts, product clusters).
  • Price history and recipe-related relations.
  • Migrations are applied before assertions when schema is not initialized.

E2E Tests: Scope and Behavior

  • Uses Jest config at apps/backend/test/jest-e2e.json.
  • Endpoint contract checks for auth, cart, products, stores, and related resources.
  • Several tests create deterministic fixture data and clean it in afterAll.
  • Some e2e tests use in-memory service mocks to avoid external dependencies.
npm run test:e2e

Recommended Local Flow

  1. Install dependencies: npm install
  2. Start the local test DB: docker compose -f docker-compose.dbtest.yml up -d
  3. Run DB tests first: npm run test:db
  4. Run e2e tests: npm run test:e2e
  5. Run full unit suite when needed: npm test
