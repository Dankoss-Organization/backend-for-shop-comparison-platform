Logging

Structured logging guidance for backend services, workers, correlation IDs, and safe production output.

Goals

  • Emit machine-parseable JSON logs.
  • Include request correlation and trace identifiers.
  • Avoid sensitive data in logs.

Recommended Schema

Use single-line JSON objects in production. The example below shows the standard fields that should be present when they are available. 

{
  "timestamp": "2026-05-26T12:34:56.789Z",
  "level": "info",
  "service": "backend",
  "env": "production",
  "message": "Product search executed",
  "correlationId": "req-123",
  "traceId": "trace-abc",
  "spanId": "span-001",
  "component": "search",
  "meta": {
    "q": "apple",
    "limit": 20,
    "durationMs": 42,
    "results": 12
  }
}

Template

Treat the following shape as the default log contract for request, worker, and error events. Fields marked optional can be omitted when they are not relevant. 

{
  "timestamp": "ISO-8601 timestamp",
  "level": "error|warn|info|debug|trace",
  "service": "backend",
  "env": "development|staging|production",
  "message": "Human-readable summary",
  "correlationId": "request-scoped id",
  "traceId": "distributed trace id (optional)",
  "spanId": "trace span id (optional)",
  "component": "search|worker|db|queue",
  "meta": {
    "durationMs": 42,
    "entityId": "prod-123",
    "count": 12
  },
  "error": {
    "type": "HttpError",
    "message": "429 Too Many Requests",
    "stack": "Error: 429..."
  }
}

Examples

Info event

Normal business event for request completion or job progress.

{
  "timestamp": "2026-05-26T12:34:56.789Z",
  "level": "info",
  "service": "backend",
  "env": "production",
  "message": "Cart total recalculated",
  "correlationId": "req-123",
  "component": "cart",
  "meta": { "cartId": "cart-45", "items": 3, "durationMs": 18 }
}

Warn event

Recoverable problem where the request still succeeds, but something is suboptimal.

{
  "timestamp": "2026-05-26T12:35:12.004Z",
  "level": "warn",
  "service": "backend",
  "env": "production",
  "message": "Search returned partial results",
  "correlationId": "req-124",
  "component": "search",
  "meta": { "q": "milk", "fallbackUsed": true, "durationMs": 91 }
}

Error event

Failure event with structured error details and a small metadata payload.

{
  "timestamp": "2026-05-26T12:35:01.123Z",
  "level": "error",
  "service": "backend",
  "env": "production",
  "message": "Failed to index product",
  "correlationId": "req-125",
  "traceId": "trace-xyz",
  "component": "indexer",
  "meta": { "productId": "prod-123", "attempt": 2 },
  "error": {
    "type": "HttpError",
    "message": "429 Too Many Requests",
    "stack": "Error: 429\n at ..."
  }
}

Key Notes

  • Log to stdout/stderr in containers.
  • Keep one event per line so log collectors can parse records safely.
  • Keep `meta` small and structured.
  • Redact secrets and sensitive payloads.
  • Include `correlationId` on every request-scoped log entry.
